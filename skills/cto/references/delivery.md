# Разработка и приёмка

## Спецификация и тикеты

Когда требования ещё формируются, используй вопросы и документацию из `grill-with-docs`. Для большой работы с открытыми решениями используй подход `wayfinder`. Спецификацию готовь по структуре `to-spec`. Вадим согласует требования и условия приёмки один раз. В пределах согласованных требований и полномочий сам утверждай архитектурные улучшения и их спецификации.

Разбей утверждённую спецификацию по методике `to-tickets`. Каждый тикет даёт один проверяемый результат, содержит ссылки, критерии приёмки и реальные зависимости. Уточняй критерии внутри согласованной спецификации самостоятельно. Оцени объём чтения, вывода инструментов, правок и проверок. Если работа может вытеснить необходимый контекст, раздели её на задачи до запуска. Для подтверждённого остатка контекста оставляй запас на проверки. При неполной наблюдаемости фиксируй оценку и указывай, какие измерения неизвестны.

Веди очередь в GitHub Issues через профильное подключение. Сверяй дубли перед созданием тикета. Используй закрытый трекер проекта или принятый для проекта резервный трекер. Связывай зависимости штатными средствами трекера, если они доступны в подключении. Иначе храни ссылки на блокирующие задачи в тикете. Порядок работы с PR и слияния определяют правила проекта и [Ai Workspace](https://github.com/vadimlarkin/ai-workspace/blob/main/docs/daily-project-integration.md).

## Выдача и восстановление работы

Храни в тикете связь со спецификацией, зависимости, владельца запуска, статус, рабочий чат, ветку, PR, проверенный коммит и следующий шаг. Перед созданием чата запиши намерение запуска. В стартовом поручении передай полный адрес тикета, критерии, исходный коммит, рабочую копию, ограничения, ожидаемые проверки и способ вернуть результат. Точная ссылка на исходное поручение сохраняет границы полномочий. Модель исполнителя выбирай по сложности задачи.

Открывай по одному ответственному рабочему чату на готовый тикет в том же проекте Codex в пределах прямого поручения Вадима. Для обмена между чатами используй данные пользователем полномочия. Если отправка недоступна, сверяй статусы по чатам и веди обратную связь в согласованном журнале или тикете. Если реализация разрешена, а отдельный чат недоступен, выполни доступную работу в текущем чате или через разрешённых исполнителей и запиши фактический способ работы. Для правок используй изолированную рабочую копию с согласованной веткой. Независимые задачи запускай параллельно с учётом пересечений и возможностей проекта.

Зависимая задача может стартовать от принятого и проверенного коммита предшественника, если правила проекта позволяют и достаточно этой версии кода. Передай точные коммиты и укажи связи между PR. При смене проверенной основы повтори затронутые проверки. Если необходимы слияние, развёртывание или доступ, дождись именно этого результата и веди независимую работу.

При потере ответа или смене чата CTO найди результат первой попытки по полному адресу тикета. Сверь чаты в проекте, записи запуска, ветку и PR. Привяжи найденный чат и продолжи в нём. Повтори запуск, только когда подтверждено, что первый чат не был создан или предыдущий исполнитель завершил работу и передал изменения. При неопределённом исходе веди независимые задачи и сохраняй состояние сверки. Асинхронный идентификатор ожидания храни как ожидающую попытку, пока Codex не выдаст готовый идентификатор чата.

## Приёмка и архив

Исполнитель реализует тикет по подходу `implement` и использует `tdd` для согласованных проверок поведения. Получи ссылку на PR, точный коммит и фактические результаты. Проведи обе проверки из `code-review` — по требованиям и правилам проекта. Связывай приёмку с проверенным коммитом. Если нужный результат ещё не готов, зафиксируй конкретное замечание и продолжи исправление в рабочем чате.

После выполнения всех условий тикета запиши в трекере результат, доказательства проверки, принятый коммит, ссылку на PR при наличии и ссылку на рабочий чат. Затем архивируй принятый рабочий чат через Codex и проверь его появление в архиве. Сохрани связь с тикетом для последующего поиска.
