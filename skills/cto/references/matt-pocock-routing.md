# Как CTO выбирает навык Matt Pocock

## Выбор и передача задачи

Сначала назови результат текущего шага. Уточни, что уже есть на входе: симптом, нерешённый вопрос, согласованная спецификация, готовый тикет или diff. Найди соответствующую строку ниже. При нескольких кандидатах прочитай их полные `SKILL.md`, сравни входы и выбери тот, чей результат нужен следующим. В поручении исполнителю передай выбранный навык, входные материалы и способ проверить результат. После получения результата реши, нужен ли следующий навык.

В колонке «Вызов» **по задаче** означает, что навык допускает автоматический выбор. **Явный** соответствует `disable-model-invocation: true` у автора. CTO может объяснить, какой явный вызов подойдёт, и поручить исполнителю работу по описанной методике в пределах полномочий. Штатный запуск такого навыка требует явного выбора пользователем. Перед применением сверь правила именно той версии, которая доступна исполнителю, и прочитай её инструкцию вместе с нужными для задачи приложениями.

## Если навыка нет у исполнителя

Проверь доступные навыки и установленную копию по имени, пути и происхождению. Ручной режим вызова или отсутствие в списке автоматического выбора сами по себе не требуют установки. Если пакет действительно отсутствует и нужен для текущей задачи, Вадим разрешил CTO поручить исполнителю установку без повторного согласования. Передай ему следующий порядок, затем прими результат по источнику, коммиту и установленному пути.

1. Возьми каталог по ссылке из таблицы. Через профильный GitHub-коннектор прочитай дерево на выбранном полном SHA, инструкцию и нужные ей файлы. Проверь зависимости и совместимость с инструментами проекта. Для Claude-специфичных операций уточни наличие самой среды.
2. Установи только нужный каталог со всеми вложенными файлами штатным способом проекта. При работе с GitHub получай файлы через его коннектор. Сверь состав и байты с выбранным коммитом до размещения. При совпадении имени с другим пакетом используй отдельную проектную область и обращайся к пакету по происхождению и пути. Принятые общие снимки обновляются по порядку Ai Workspace.
3. Запиши в рабочем тикете или чате источник, SHA и путь. Проверь чтение установленной инструкции и её относительных ссылок, затем доступность в контексте исполнения. Если перечень навыков обновится только в следующей сессии, укажи это отдельно. Права на внешние действия определяет поручение, даже когда установка разрешена.

## Частые развилки

- **Тяжёлая функция, в том числе с готовой спецификацией.** Поручи исполнителю [обязательную проверку прототипом](delivery.md#прототип-тяжёлой-функции). Прими вывод, запроси уточнённую спецификацию и выдай реализацию проверенного решения.
- **Небольшой готовый тикет.** Передай исполнителю `implement`, а при согласованном тестируемом поведении также `tdd`. Для приёмки передай в `code-review` исходную точку и критерии. Полный цикл планирования здесь избыточен.
- **Приложение стало медленнее.** Поручи диагностику по `diagnosing-bugs`, запроси воспроизводимое измерение и критерий исправления. Если причина в архитектуре модуля, затем подключи `codebase-design`.
- **Неясны требования.** Когда ответ знает владелец решения, подойдёт интервью. Когда ответ знает внешний участник, выбери `to-questionnaire`. Для проверяемого факта из внешней документации выбери `research`, для вопроса о поведении работающей функции — `prototype`.
- **Большая работа.** Поручи исполнителю проработку открытых зависимых решений по `wayfinder`, затем подготовку спецификации по `to-spec`. Для нарезки работы подойдёт `to-tickets`; для исполнения готового графа — `implement-spec`. При выдаче тяжёлой функции действует правило прототипа выше.

## Состав справочника

Срез [репозитория автора](https://github.com/mattpocock/skills/tree/abeeaf95660ba9e8b7c753eb38f441ca707a8823/skills) включает все 39 каталогов с `SKILL.md`. Первые две группы входят в [манифест плагина](https://github.com/mattpocock/skills/blob/abeeaf95660ba9e8b7c753eb38f441ca707a8823/.claude-plugin/plugin.json). Остальные доступны в исходном репозитории. При обновлении среза поручай исполнителю сравнить полный список `skills/**/SKILL.md` по дереву нового коммита с таблицами и проверить изменившиеся инструкции, ссылки и режимы вызова. Если задача требует навыка, появившегося после этого среза, поручи исполнителю проверить его у автора и применить тот же порядок установки.
